# 语音查询打折/优惠商品（网关工具）

日期：2026-11-11
状态：待确认

## 目标

用户对助手说「今天有什么打折的」「帮我找找耳机的优惠」，助手通过网关新增的
`query_deals` 工具查询最新好价，并用语音播报结果。不做页面、不改客户端、不改协议。

## 非目标

- 不新增客户端页面、卡片或 `media.*` 事件。
- 不做商品详情页、购物车、下单。
- 不注册联盟账号、不购买第三方套餐、不引入需要 Key 的服务。
- 不落价格快照，不做历史价格曲线。

## 数据源

抓公开页面「什么值得买 · 精选好价」：`https://www.smzdm.com/jingxuan/`。

2026-11-11 实测：

- 页面可直接访问（HTTP 200，约 20 条/页），列表随站点实时更新。
- 每页含标题、现价、商城、发布时间、优惠标签（历史低价 / 365 天新低 / 手慢无等）。
- 站内搜索接口被 WAF 拦截，因此关键词查询改为抓最近 1–3 页后在网关本地过滤，
  不把用户关键词发给第三方。

## 方案

网关新增工具文件 `gateway/src/service/tools/dealsTool.ts`，在 `tools/index.ts` 注册。

调用流程：

1. LLM 判断用户在问优惠/打折，调用 `query_deals({ keyword?, limit? })`。
2. 工具抓取 `DEALS_SOURCE_URL`（默认精选好价第一页）；有 `keyword` 时并行抓
   `p2/`、`p3/`，合并去重。
3. 用 cheerio 解析 `li.J_feed_za`，提取标题、价格、标签、商城、时间、链接。
4. 按关键词过滤（标题 + 标签 + 商城），按页面顺序取前 `limit` 条。
5. 返回本地化纯文本，由 LLM 组织成一句语音播报。

缓存：按页面 URL 做内存缓存，默认 60 秒；并发请求复用同一个 Promise，避免重复抓取。
失败降级：单页失败不影响其它页；全部失败返回「暂时查不到」；空结果返回「没找到」。
不编造折扣：只播报页面上的现价与标签，不计算页面没有的折扣率。

## 工具接口

```ts
name: 'query_deals'
input: {
  keyword?: string   // 商品关键词，如「耳机」「咖啡机」；为空则返回最新好价
  limit?: number     // 1–5，默认 3
}
```

播报示例：

> 查到 3 件最新好价：1. 全棉时代婴儿棉柔巾 80 抽 24 包，现价 200 元，京东，历史低价；
> 2. 大艺无刷电动扳手，现价 106.84 元，京东，365 天新低；3. ……。价格变得快，下单前以商品页为准。

## 配置

新增网关环境变量（`.env.example` 同步）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `DEALS_SOURCE_URL` | `https://www.smzdm.com/jingxuan/` | 好价列表首页；换源只改这里 |
| `DEALS_CACHE_TTL_MS` | `60000` | 列表缓存时间 |
| `DEALS_KEYWORD_PAGES` | `3` | 关键词查询最多抓几页（每页 20 条） |

第三方地址只来自网关配置，客户端不传 URL；工具不上报用户位置、设备号或关键词给第三方。

## 测试

- 解析固定 HTML 片段，得到标题/价格/标签/商城/时间。
- 关键词过滤、`limit` 截断、空结果文案。
- 抓取失败降级、HTTP 非 200 降级。
- 缓存：TTL 内第二次调用不再触发 fetcher。
- `createToolkit` 登记了 `query_deals`。
- `npm run test` + `npm run type-check` 全绿。

## 风险

- 抓取依赖页面结构，站点改版或反爬会导致工具失效；失效时明确回复「查不到」，不编造。
- 公开页面的抓取可能受站点条款限制，仅用于个人助手；若后续要长期稳定，换成官方/付费源时只替换
  data source 实现，工具与播报层不变。
