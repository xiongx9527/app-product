# 9529 管理面板页面需求

> 状态：需求梳理（未实施）。日期 2026-11-20。
> 对象：`model-proxy/voice/admin_panel.py` 内嵌的 `/admin` 单页面板。
> 目标形态：**左侧导航 + 独立页面**，取代当前"单页多卡片 + 多层 tab 嵌套"。

## 一、现状全景

当前是单页滚动 + 4 张可折叠卡片：

| 卡片 | 角色 | 内容 |
|---|---|---|
| 配置卡（默认折叠） | admin | 5 tab：LLM / 向量 / ASR / TTS / 安全；安全 tab 再套 3 子 tab：安全配置 / API Key 管理 / 账号管理；ASR tab 再套 3 子 tab：模型 / 热词 / 审核 |
| 限流策略卡（默认折叠） | admin | 策略列表 CRUD + key 绑定区（开关+策略多选） |
| 测试卡（默认折叠） | operator+ | 4 tab：LLM / 向量 / ASR / TTS |
| 日志卡（展开） | 所有 | 纯文本日志 + 刷新，默认最近 200 行 |

顶部 header：标题、账号 + `[角色]`、修改密码按钮、文档 / WS 文档链接、中/EN 切换、退出登录。

端点按角色：viewer 6 个只读、operator +6 个测试类、admin 全部（含 users / api-keys / rate / config / corrections / sync / 模型池等）。

## 二、当前问题

1. **身份/访问管理分散**：账号管理、API Key 管理藏在"安全"tab，限流策略却是独立卡——同类功能两处放。
2. **配置卡嵌套过深**：5 个 tab，安全 tab 里再套 3 个子 tab，ASR tab 里再套 3 个子 tab，最多三层。
3. **配置与测试重复**：LLM/向量/ASR/TTS 在配置卡和测试卡各出现一遍，测试卡默认折叠，来回切换。
4. **viewer 体验单薄**：登录后只能看日志卡，status 等只读数据没有专门页面呈现。
5. **key 相关割裂**：API Key 的创建/编辑在"安全>API Key 管理"，限流开关/策略绑定却在"限流策略卡"，同一把 key 要在两处改。
6. **卡片折叠状态不记忆**：刷新后全部回到默认折叠态。

## 三、目标页面结构：左侧导航 + 独立页面

```
┌─────────┬──────────────────────────────────┐
│ 侧边导航 │  页面内容区（点击导航切换，不滚动）   │
│         │                                  │
│ 概览     │  [当前页面标题 + 说明]             │
│ 模型配置 │  [该页面的表格/表单/操作]           │
│ 访问控制 │                                  │
│  · 账号  │                                  │
│  · Key   │                                  │
│  · 限流  │                                  │
│ 连通测试 │                                  │
│ 运行日志 │                                  │
└─────────┴──────────────────────────────────┘
```

导航项按角色动态显示（viewer 只看概览/日志，operator +连通测试，admin 全部）。

## 四、各页面需求

### 1. 概览（所有角色）
- 服务状态：`/admin/api/status` —— pid 存活、health、版本、存储状态、鉴权/限流开关状态
- 只读呈现，无编辑
- viewer 登录后默认落此处（替代当前只能看日志）

### 2. 模型配置（admin）
把当前配置卡的 LLM / 向量 / ASR / TTS 四个 tab 平铺为**单页分段**（不再是 tab 嵌套）：
- **LLM 段**：启停(auto/on/off)、上游分组表格（默认/provider/地址/Key/模型/协议/厂商，增删改）+ 保存
- **向量段**：同 LLM 结构，独立存储
- **ASR 段**：模型勾选表（内置/上游、设默认、测可用、刷新候选）+ 上游地址/Key + 保存
- **热词段**（从 ASR 子 tab 提升为独立段）：搜索、增删改、启用/禁用、审核、分页、加变体
- **TTS 段**：上游地址/Key/音色/默认模型 + 保存
- 每段一个保存按钮，互不影响

### 3. 访问控制（admin）—— 合并当前散落的三处
一个页面，顶部三个子页签（这次是**平级子页签，不再嵌套在"安全"tab 下**）：

- **账号**：用户列表（用户名/角色/状态/内置标记）、增删改角色、重置密码、禁用/启用；内置管理员只读；顶栏"修改密码"保留
- **API Key**：Key 列表（前缀/备注/生效-失效/绑定IP/状态）、新增（明文仅显示一次+复制）、编辑、启停、删除
- **限流**：策略列表（4 维阈值/启用/默认，默认策略禁删禁停）+ 每个 key 的"限流开关 + 绑定策略"多选
  - 迁移重点：把限流策略卡里的"key 绑定区"和 API Key 管理的 key 列表合并——在 Key 子页签直接看到该 key 的限流开关与绑定，不用来回切

### 4. 安全设置（admin）
从"安全"tab 的安全配置部分独立出来：
- `VOICE_API_KEY_AUTH` 开关（红色风险提示，说明影响所有对外接口）
- `VOICE_IP_ALLOW` 全局白名单
- 全局 `RATE_LIMIT_ENABLED` 开关
- 保存按钮

### 5. 连通测试（operator+）
把当前测试卡的 4 个 tab 改为单页分段（与模型配置的段一一对应，便于对照）：
- LLM / 向量 / ASR / TTS 四段，每段保留现有输入项（provider/model/协议/流式/思考开关/请求头表/body 表/录音/播放/合成）
- ASR 段保留 HTTP 与 WS 两种测试入口
- 顶部一个全局 Bearer Key 输入框

### 6. 运行日志（所有角色）
- 保持现状（纯文本 + 刷新 + 行数控制），作为独立页面
- 增加：按关键词过滤、自动刷新开关（可选）

## 五、角色与导航映射

| 导航项 | viewer | operator | admin |
|---|---|---|---|
| 概览 | ✓ | ✓ | ✓ |
| 模型配置 | — | — | ✓ |
| 访问控制 | — | — | ✓ |
| 安全设置 | — | — | ✓ |
| 连通测试 | — | ✓ | ✓ |
| 运行日志 | ✓ | ✓ | ✓ |

后端 `require_role` 分级已就位，页面重排时按此映射控制导航项显示；**后端拦截是真防线，前端隐藏仅辅助**。

## 六、交互约定

- 左侧导航固定，页面内容区切换；浏览器刷新后**记住当前页面**（localStorage）
- 不再用卡片折叠（去掉"默认 collapsed"），改由导航切换
- 所有表单保存后行内状态提示，不用 `uni.showToast` / 不弹浮层（沿用既有偏好）
- 错误统一 `alert(fmtErr(detail))`；危险操作（删除、重置密码、删 Key/策略）用 `confirm()`
- i18n：所有可见文案走 zh-CN / en 两字典，新增文案两处都加
- 表格复用 `.admin-table`（自动列宽），账号列 `col-name` 不截断
- 模态框复用 `showModal`（返回 `'keep'` 保持打开的语义）

## 七、迁移路径（建议分步）

1. **骨架**：搭左侧导航 + 页面容器 + localStorage 记忆，把现有 4 张卡整体搬进对应页面（行为不变，先跑通）
2. **访问控制合并**：把账号/API Key/限流三块收敛到"访问控制"页，消除 key 相关割裂
3. **配置卡拆层**：5 tab + 嵌套子 tab 改为单页分段，热词提升为独立段
4. **安全设置独立**：从配置卡抽出
5. **测试卡对齐**：4 tab 改分段，与配置段一一对应
6. **清理**：删除旧卡片代码与折叠逻辑，补 i18n 与测试

每一步都保持后端端点不变（只动前端呈现与导航），降低风险。
